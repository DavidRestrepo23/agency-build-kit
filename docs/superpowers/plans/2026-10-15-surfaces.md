# Ciclo 1.1 — Surfaces Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Soportar estilos de caja reutilizables (`surfaces`) en el site-spec y en el adaptador Webflow, más la excepción `scaleApproved` del gate de raster y `/wf-setup --update`.

**Architecture:** `surfaces` se declaran en `tokens.yaml`, se validan en `validate-spec`, se convierten en clases globales `surface-<name>` en `plan-setup` y se apilan sobre la clase de grupo/sección en `plan-section`. Cambios de Markdown documentan el flujo.

**Tech Stack:** Node ≥ 22 ESM, `node:test`, `ajv`, `yaml`, esbuild (sin cambios).

**Spec:** `docs/superpowers/specs/2026-10-15-surfaces-design.md` (cambios sobre `docs/superpowers/specs/2026-10-15-webflow-builder-design.md`).

## Global Constraints

- Todo lo del ciclo 1 sigue vigente (CLIs JSON + exit code, spec neutral, rem base 16, Client-First).
- Nombre de surface kebab-case; clase Webflow `surface-<name>`.
- Bordes en px; radios en rem vía `pxToRem`; padding y colores ligados a variables.
- `npm run build` regenera `plugins/*/scripts` después de cambiar `src/`; se commitean.

## Review Focus

1. **Surface que referencia un radio inexistente** (`radius: huge` sin `radii.huge`): debe ser error de validación, no un `pxToRem(undefined)` que lance en `plan-setup`. → Task 2.
2. **`surface` en un hijo que no es `group`** (ej. `text`): debe rechazarse por schema. → Task 2.
3. **Surface solo con padding responsive**: entradas `medium`/`small` solo cuando el token cambia, sin estilos vacíos. → Task 3.
4. **Sección con `background` y `surface`**: error explícito. → Task 2.
5. **Cambio en la definición de una surface** no debe invalidar secciones ya construidas (hash estable). → Task 4.

```js
  for (const [name, surface] of Object.entries(spec.tokens.surfaces ?? {})) {
    const cls = `surface-${name}`;
    const props = {};
    const vars = {};
    if (surface.background) vars['background-color'] = variableName(surface.background);
    if (surface.border) {
      for (const side of SIDES) {
        props[`border-${side}-width`] = `${surface.border.width}px`;
        props[`border-${side}-style`] = 'solid';
        vars[`border-${side}-color`] = variableName(surface.border.color);
      }
    }
    if (surface.radius !== undefined) {
      for (const corner of ['top-left', 'top-right', 'bottom-right', 'bottom-left']) {
        props[`border-${corner}-radius`] = pxToRem(spec.tokens.radii[surface.radius]);
      }
      props.overflow = 'hidden';
    }
    const padding = { main: {}, medium: {}, small: {} };
    for (const [axis, sides] of [['y', ['top', 'bottom']], ['x', ['left', 'right']]]) {
      const token = surface.padding?.[axis];
      if (!token) continue;
      for (const [bp, { name: variable }] of Object.entries(responsiveVariableNames(token, spec.tokens.spacing[token]))) {
        for (const side of sides) padding[bp][`padding-${side}`] = variable;
      }
    }
    style(cls, 'main', props, { ...vars, ...padding.main });
    for (const bp of ['medium', 'small']) {
      if (Object.keys(padding[bp]).length) style(cls, bp, {}, padding[bp]);
    }
  }
```

````markdown
## Surfaces (box styles)

Reusable box styles live in `tokens.yaml` under `surfaces` and are referenced with `surface: <name>` on a `section` or a `group` child:

```yaml
surfaces:
  card:
    background: neutral.glass                          # color token
    border: { color: neutral.border-strong, width: 2 } # px
    radius: card                                       # key in radii
    padding: { x: space.xl, y: space.xl }              # spacing tokens
```

- Every property is optional, but a surface needs at least one.
- A section uses either `background` or `surface`, never both.
- Name every repeated card/badge/panel style; a box style used once still gets a surface.

## Raster exceptions

A raster below 2x needs `scaleApproved: "<reason>"` in the manifest (approved by the developer); `/build-audit` lists every exception in its report.
````
